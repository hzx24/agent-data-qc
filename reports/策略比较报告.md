# 两种准入策略比较与推荐

**推荐采用 balanced（保留过程价值）作为本轮默认策略。**两策略使用相同严重缺陷与证据不足规则；conservative（完整边界与来源隔离）额外要求起止完整，并暂缓所有已标记评测来源。当前业务明确要训练探索、失败与重试，尚未规定禁止评测来源；增加这两道门槛会显著减少相关过程，而不能证明任务更正确。

## 范围、策略与复现

固定 GOAT-AI/gatcv6 revision `216fb6e2c9449dd8eeab0a3b9233e89ea08d1f7a`，公开六表、1,189条轨迹。两次运行原始文件哈希、包代码哈希、依赖、种子20261020及其他配置均一致；检查无失败。比较脚本验证运行产物哈希后再比较，不把不同版本混在一起。

| 项目 | balanced | conservative |
|---|---|---|
| 无效参数JSON、孤立返回等明确缺陷 | 排除 | 相同 |
| schema兼容疑问、关键移除文本、未解释跨表冲突等 | 暂缓 | 相同 |
| 无工具调用 | 按本轮目标排除 | 相同 |
| 合法失败、重试、未知状态 | 不单独阻断 | 相同 |
| 起点无真实用户请求，或末尾无助手文本回答 | 风险标记，允许保留合法中间行为 | 暂缓（STRICT_BOUNDARY） |
| is_eval=true | 标记来源风险，不据此断言真实重叠 | 暂缓（STRICT_EVAL） |

两个新增条件是训练目标/来源门槛，不是新增损坏检测器。保守策略与“丢掉失败”不同，仍可保留符合边界和来源要求的失败过程。

一条命令重跑两策略并生成差异文件：

```bash
.venv/bin/python scripts/compare_policies.py --run
```

详细结果在 `outputs/balanced/`、`outputs/conservative/`，比较结果在 `outputs/comparison/`。

## 全量结果：保留与牺牲

| 指标 | balanced | conservative |
|---|---:|---:|
| 入选轨迹 | 862（72.50%） | 433（36.42%） |
| 暂缓轨迹 | 245 | 674 |
| 排除轨迹 | 82 | 82 |
| 入选轨迹内工具调用 | 35,117 | 21,852 |
| 入选轨迹内已记录失败调用 | 1,666 | 751 |
| 入选轨迹中包含失败的轨迹 | 383 | 201 |
| 原始步骤推导的失败后四步成功窗口 | 1,439 | 671 |
| 入选轨迹内状态未知调用 | 1,161 | 199 |
| 入选中评测标记/开放边界轨迹 | 332 / 191 | 0 / 0 |
| 入选中共享模板轨迹 | 540 | 178 |

保守策略当前隔离429条原可入选轨迹，其中13,265次工具调用、915次已记录失败、768个后续成功窗口随整轨迹一起暂缓；损失约37.8%的balanced工具调用及54.9%的已记录失败调用。它减少可观测的来源/边界暴露，但不能据此推断真实污染率、误报率或模型收益更好。

balanced保留这些多步过程，代价是接受开放边界、评测来源及更多状态未知的记录。conservative保留起止完整且未标评测的过程，代价是隔离近半数原可入选轨迹，并使失败过程减少得更明显。两者均未保证任务成功或实现正确；窗口成功不等于原故障被修复。conservative仍保留178条共享模板轨迹，未标评测也不保证无外部重叠。

| 入选 → 暂缓 | 429 |

429条变化互斥分解为：仅评测标记238条，仅边界97条，两者同时94条。不存在入选转排除；另有143条虽增加严格策略原因码，最终处置未变，单独导出而不混入429条。

完整ID、前后处置、原因、源行、工具行为计数与策略证据见 `decision_changes.csv` 和 `decision_changes.jsonl`。以下三个真实案例均已位于原118条队列中，仅作差异解释，不替代30条正式复核；详细证据另存 `reports/策略比较案例.jsonl`。

- **7daf4462d83e7964ecc06877（原始表/消息表第128行）**：用户要忽略data目录。原始步骤7的git add因忽略规则失败，步骤8改为只添加.gitignore后成功，展示有针对性的修正；但末尾步骤12的amend结果为空、状态未知，消息18是空工具返回，没有最终回答。balanced保留中间过程，conservative仅因边界暂缓。不声称最终amend完成；若业务要求终局完成证据，应暂缓。
- **e8e7875ed949d0b4242d3da4（第738行）**：电网调度任务，24次工具调用、2次已记录失败；大文件读取失败后增加limit，缺numpy后继续处理依赖并重跑。首尾完整，两策略差异仅来自terminal-task评测标记。balanced保留恢复过程，conservative隔离来源。步骤24的pip管道虽ok=true，结果却提示PEP668限制，证明状态成功不等于语义成功；不能把本例作为可靠任务成功标签。若目标评测包含此任务，应隔离。
- **753530dd642d338581edde8e（第1075行）**：修复pytest路径显示问题，步骤4的grep遇EACCES，步骤5改用shell grep获得结果；但末尾仍在读测试文件，没有最终修复结论，且有repository-task标记。balanced保留可核查的故障应对，conservative因边界和来源同时暂缓。原始路径含swebench-workspaces，是应重点核对目标评测的具体线索；当前未拿到目标评测集，不能把修复正确性或无污染当成事实。

## 人工预算与推荐依据

两策略每批最多118条（floor(1189×10%)），均分配94条疑难优先、24条固定种子审计。**本批次两队列ID完全相同**：共有严重/证据疑问影响分高于新增边界/来源门槛，前94名相同，剩余集合的种子抽样也相同。

| 指标 | balanced | conservative |
|---|---:|---:|
| 暂缓候选数 | 245 | 674 |
| 实际队列内暂缓/入选 | 96 / 22 | 112 / 6 |
| 暂缓队列覆盖比例 | 39.2% | 16.6% |
| 未入队暂缓 | 149 | 562 |

不能说保守策略实际多用了人工：两者都是118个相同ID，但新增429条暂缓仅16条在队列中，另外413条直接进入未入队暂缓。即使把全部118个名额都用于疑难，仍至少剩127条或556条，不能靠“后续人工全部处理”回避取舍。超预算保持暂缓，排队不自动放行，不把两策略队列当作两批预算。

推荐balanced的理由是：它与失败恢复目标更一致；两策略共用的硬检查已保留，而额外门槛隔离的是来源和边界，不是已证实错误。保守方案减少相关风险暴露的收益真实存在，但当前缺少目标评测重叠及训练效果证据，不足以支持牺牲这些过程。这里不是认定429条全部优质，也不是主张忽略来源风险。

## 哪些证据会改变推荐

1. 业务改为只训练完整终局回答、且不允许片段训练，或规定禁止一切预设评测来源：采用对应保守门槛；两项都成立则改用conservative。
2. 提供独立评测集并核实重叠：按真实重叠隔离任务或来源组；不必扩大到全部is_eval轨迹。明确评测政策可以批量决定来源，不必逐条耗费人工名额。
3. 分层复核发现开放边界经常缺少关键动作反馈，或固定评测/计算预算的对照训练证明额外过程损害目标能力：收紧具体规则。当前没有这类效果实验，不编造改进幅度或准确率。
4. 补齐原始schema/产物，或允许依赖完整的片段训练及局部损失屏蔽：重新评估暂缓部分，可能采用比两者都更细的准入方式。

当前50项正反例及集成测试通过（含两条明确标注的真实结果回归摘录，其余为合成边界/工程测试），其中比较测试覆盖同数据/同代码约束、规则重叠不重复计数、原因变化与处置变化区分及原始数据变动拒绝比较。截断标记误报修复后已重跑两策略全量扫描，本报告的处置、队列、保留计数与推荐均不变；仅一条轨迹撤回截断理由，仍因独立schema问题暂缓。详见`reports/truncation_fix/README.md`。这些测试不构成全量人工金标准。30条真实样本已由提交者逐条人工核对；外部去污染、模型模板与训练收益验证仍待完成。
