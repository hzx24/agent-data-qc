# Agent轨迹数据准入决策报告

## 1. 目标、证据与本轮优先级

建议采用balanced准入策略，在通用可消费性检查后保留合法失败、重试和开放结尾的工具过程。它不是任务正确性认证。数据固定为GOAT-AI/gatcv6 revision `216fb6e2c9449dd8eeab0a3b9233e89ea08d1f7a`的公开sample：六表、1189条轨迹、92365步、52617次工具调用；没有获取另行授权的117796条完整数据。原压缩文件和发布校验清单均保留，messages用于训练表示，trajectories用于核证。

资源有限，本轮选择六类问题，按可消费性影响与已有证据优先，而不按“报错越多越好”排序：

| 优先问题 | 实际发现及选择依据 |
| --- | --- |
| 参数内容与工具schema | 216条与发布schema不兼容；其中84条有明确动作内容缺失。参数错误会直接影响工具行为监督，但重建schema不是原工具真值 |
| 跨步骤调用—返回协议 | 验证ID唯一、引用顺序及返回归属，允许非相邻/并行返回；真实样本未命中配对缺陷，合成反例验证规则仍必要 |
| 失败、未知与恢复语义 | 452条含已记录失败；36条的恢复视图无法唯一关联。避免将窗口成功、未知状态误作任务成功或失败 |
| 跨表引用与一致性 | 按trajectory_id+i核对调用视图、计数和状态；4条结果差异不能证明等价，暂缓而不武断判损坏 |
| 关键证据移除/截断 | 43条含WITHHELD；修复后1条含68处独立截断提示。主表完整而视图仅合法前缀的情况不阻断 |
| 重复与评测来源线索 | 422条标为评测、674条共享开头模板；不把来源标记或共享开头直接当污染/全文重复 |

暂不重放代码、全面审计隐私或做外部评测去污染，代价是可能保留语义错误、隐私残留和未知重叠。没有目标tokenizer/模板，不以字符长度冒充token预算；没有原生工具契约，不擅自补参。后续优先补目标评测集、工具定义及可核验环境/产物。

## 2. 分类、准入与预算

明确数据缺陷，例如无效参数JSON、孤立工具返回，按适用契约排除；关键证据不足，例如移除正文、重建schema冲突，暂缓并注明所缺证据；合法但不匹配本次目标，例如零工具调用，按目标排除而不计为损坏。未知状态、合法失败与无最终回答不单独阻断balanced。损坏行、缺表、校验/检查失败均显式报告，禁止静默跳过后宣称完整通过。

跨步骤证据不只核对相邻文本：调用ID追踪返回；失败视图按工具、参数及结果寻找候选，仅唯一关联后验证窗口；跨表按原步骤定位视图。非唯一恢复关联不否定完整messages，但禁止将其派生成功含义当监督真值。

每批人审最多floor(1189×10%)=118条：94条按可改判影响、调用价值上限100及种子哈希排序，24条从剩余记录固定种子审计。优先级是透明启发式而非错误概率。超预算疑难继续暂缓，入队也不自动放行；两策略不能各用一份预算。

## 3. 两策略实测与推荐

两策略使用相同数据、代码、依赖与种子，仅conservative额外要求完整起止和隔离is_eval来源。

| 全量指标 | balanced | conservative |
| --- | ---: | ---: |
| 入选 / 暂缓 / 排除 | 862 / 245 / 82 | 433 / 674 / 82 |
| 入选调用 / 已记录失败调用 | 35117 / 1666 | 21852 / 751 |
| 人审队列 / 未入队暂缓 | 118 / 149 | 118 / 562 |

82条排除全部是零工具调用，不是已证明损坏。429条由入选转暂缓：仅评测来源238条、仅边界97条、两者94条；另143条仅增加原因而处置未变。全部ID及证据在`outputs/comparison/decision_changes.jsonl`，不以挑选案例替代完整差异。

conservative降低来源/边界暴露，却额外隔离13265次调用和915次已记录失败，没有证明任务更正确。balanced保留这些过程，承担未核验污染和不完整终局的风险，更符合工具使用与恢复训练目标，故推荐balanced。两策略队列ID恰好相同118条，保守策略增加的疑难无法靠“以后全部人工处理”解决。

例：`7daf4462d83e7964ecc06877`步骤7添加文件失败，8改添加.gitignore后成功，最后amend无反馈；balanced保留过程，conservative因结尾暂缓。`753530dd642d338581edde8e`步骤4权限失败、5换shell搜索取得结果，具恢复价值但有评测来源和开放结尾。两例都不能据此认定整个任务成功。

若业务规定仅收完整终局或禁止评测来源，应启用对应严格门槛；若提供目标评测集，按真实重叠隔离，而非一律扩大到所有is_eval；若允许局部损失屏蔽/可靠切片，可重新评估整轨迹暂缓的代价。训练收益仍需固定评测和计算预算的实验验证。

## 4. 验证、纠偏与限制

50项自动化测试通过，覆盖缺陷正例、合法参数变体、并行/非相邻返回、失败与未知、合法视图前缀、损坏输入、预算、重复运行和证据定位。两个真实结果摘录明确标注，其余边界采用合成样例，不能算作人审。

复核发现原始表第53行步骤27的`[TRUNCATED]`是测试代码常量。初版“见标记就暂缓”误报；放弃全局关闭或豁免所有引号，采用逐标记源码语境识别，未知仍暂缓。新增7项回归/集成测试并重跑两策略全量扫描：69处阻断标记变68处加1处非阻断常量，所有非截断问题相同。该轨迹仍因独立schema冲突暂缓，处置与队列排序、策略推荐不变。完整前后材料见`reports/truncation_fix/`和`outputs/truncation_fix/`。

30条真实人工复核记录包括10条条件随机、10条规则命中、10条边界，全部在既有队列内。随机组来自有意选样后剩余13条审计子池，不代表全量。人工复核确认4条入选转暂缓，涉及单位依据、指定头名与产物冲突、控制台输出可能误转调用、关键观测全部为空；已由提交者逐条确认，人工结论与自动规则全量处置分开保存。长轨迹仅针对性阅读，未逐字验收全部代码。

本报告不报告总体准确率、误报率或训练收益；50项测试通过和一个真实误报修复均不能推出这些指标。本项目使用 Codex 辅助代码实现、测试、数据分析及文档整理。提交的 30 条样本复核记录已由本人逐条核对，最终规则、样本判断及准入建议由本人确认并负责。质检管线在普通 CPU 环境运行，不依赖付费模型 API。实际累计投入约6小时，为用户估算；单次新扫描耗时balanced 7.147秒、conservative 7.082秒，不等于开发或人审耗时。30条人工确认已完成；既有语义验收与评测去污染限制仍然保留。
